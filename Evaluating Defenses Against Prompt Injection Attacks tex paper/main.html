\block{1. Research question and safe scope}{5 points} Question / claim: Can two prompt-injection defenses reduce attack success while preserving normal-task accuracy? We will test this trade-off rather than assume either defense is effective.
Setting and threat model: We propose one fixed API LLM (GPT-4o-mini; snapshot and access to be confirmed) for sentiment classification on a public SST-2 subset. The protected goal is correct positive/negative classification following the trusted task instruction. An attacker can insert malicious instructions into untrusted review text to make the model output the fixed marker INJECTED; the attacker cannot change model weights or the system configuration.
Resources and authorization: Python, the authors' public code and data, and an authorized model API will support a controlled test harness. The proposed budget is 1,080 model calls, with a dollar cap to be agreed before testing. We will follow data/code licenses and API terms, use no private data, and test no third-party applications.

\block{2. Baseline, contribution, and evaluation}{5 points} Prior work and baseline: Building on the original benchmark, we will test whether prompt-injection vulnerabilities remain effective under a current model interface and evaluate whether simple defenses reduce attack success without significantly harming normal-task performance. Liu et al., Formalizing and Benchmarking Prompt Injection Attacks and Defenses (USENIX Security 2024), provide a common benchmark. We will reuse

Open-Prompt-Injection

's code and SST-2 setup, begin with no defense, and document changes to the model interface and marker-based success rule.
Bounded contribution: We propose two attack families: instruction override (ignore the task) and fake completion (imitate a completed response, then redirect). We will compare no defense with two separate defenses: delimiting untrusted text and explicit instructions to disregard instructions within that text. Both attacks will be tested under all three conditions, followed by comparison and failure analysis.
Experiment and metric: Use 20 tuning examples and 100 disjoint final cases, with balanced sentiment labels. Freeze prompts, case IDs, model revision, decoding settings, and scoring before final evaluation. Each condition uses the same cases and one query per case, with no adaptive retries: 6 attacked conditions plus 3 clean conditions yield 900 final calls; tuning is capped at 180 calls. Attack Success Rate is the fraction of attacked outputs matching INJECTED after whitespace normalization. Normal-task accuracy is label accuracy on clean cases; invalid outputs count as incorrect. Report each defense's ASR reduction and clean-accuracy change relative to no defense, and inspect failures.
