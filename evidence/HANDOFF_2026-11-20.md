## Read first: two changes that affect results

1. **qwen3 thinking was on in every earlier qwen run.** Ollama's OpenAI endpoint ignores
   `chat_template_kwargs: {enable_thinking: false}` and `think: false`. Only `reasoning_effort: "none"`
   turns it off. `Qwen.py` now has `thinking_parameter_style: "reasoning_effort"`, and
   `configs/model_configs/ollama_qwen3-8b_config.json` uses it.
   - With thinking on, answers that used up the 512-token cap came back empty, and runs were about 30x slower
     (35-75 s per sample, now 1-2 s).
   - **The old qwen SST-2 -> SST-2 sweep (`evidence/scoring_sweep`, the rerun folders) ran with thinking on.**
     Rerun it before using its numbers.
2. **Scorer change in `scripts/score_responses.py`.** A blank answer under `response-based` now counts as
   `blocked`, not `invalid` (`BLOCKING_DEFENSES = {"known-answer", "response-based"}`), because
   `ResponseBasedDefense.process_response` returns `""` for answers that aren't a valid label. Only
   response-based rows change. Revert it if you disagree.

## Caveats for writing up defenses

- **known-answer** works on qwen: it blocks all attacked prompts and no clean ones. On Mistral it blocks
  *everything*, because `KnownAnswerDefense.detect` compares the answer to the secret exactly and Mistral adds a
  leading space. That's a team decision: strip the answer before comparing, or report the artifact.
- **paraphrasing** gives 0% ASR on qwen, but all 100 attacked prompts get the answer `Negative`. The
  paraphrase removes the review along with the injection.
- **retokenization** undercounts: qwen echoes `I N J E C T E D` 31 times. Counting those, it's about 86, not 55.
- **response-based** only works here because `INJECTED` isn't a sentiment label.

## Running things

```bash
PYTHONPATH=. uv run python run.py --matrix-config <matrix.json> --max-parallel 1 --max-retries 2 --skip-completed
uv run python scripts/score_responses.py result/<prefix>_* --out evidence/<folder>
```
- Use `--max-parallel 1`. The default of 0 launches every experiment at once, and Ollama serves one request
  at a time anyway.
- `--skip-completed` resumes after a crash or sleep. Each experiment also resumes from its last saved sample.
- Changing a model config invalidates cached responses for that model, so move old result folders aside first.
